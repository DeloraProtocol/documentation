This page summarizes the supported third-party integration API for `@deloraprotocol/widget` 1.1.x and the optional `@deloraprotocol/widget-wallet-management` adapter package.

Most integrations center on the trading widget surface:

- `TradeWidget`
- `TradeWidgetWalletProvider`
- `useTradeWidgetWalletManagement`

The core package also exports a smaller `MyWidget` demo component and shared theming props.

## `MyWidget` and `MyWidgetProps`

`MyWidget` is a minimal example export that shares the same root theming surface as `TradeWidget`.

If you are embedding the production trade experience, use `TradeWidget`. If you need the lightweight demo component that ships with the package, use `MyWidget`.

`MyWidgetProps` extends normal root `div` props.

| Prop | Type | Description |
| --- | --- | --- |
| `theme` | `"light" \| "dark"` | Built-in theme. Default: `"light"` |
| `vars` | `Partial<MyWidgetVars>` | Theme token overrides |
| `className` | `string` | Applied to the widget root element |
| `style` | `React.CSSProperties` | Inline root styles applied after generated CSS variables |

Common `MyWidgetVars` fields include:

- `radius` for shared surface radius
- `actionButtonRadius` for the main CTA radius
- `actionButtonBg`, `actionButtonFg`, `actionButtonHoverBg`, `actionButtonActiveBg`, `actionButtonDisabledBg`, and `actionButtonDisabledFg` for the primary action colors
- `fontFamily`, `fontSize`, `lineHeight`, and `letterSpacing` for typography
- color and surface tokens such as `bg`, `fg`, `border`, `surface`, and `surfaceAlt`

See [Customize Widget](/widget/basic-setup/customize-widget) for the full theme-token surface and examples.

## `TradeWidgetProps`

`TradeWidgetProps` extends normal root `div` props, except the DOM `onError` prop is replaced by the widget error callback. `TradeWidget` also accepts a `ref` of type `TradeWidgetHandle`.

| Prop | Type | Description |
| --- | --- | --- |
| `config` | `TradeWidgetConfig` | Required widget runtime config object |
| `filters` | `TradeWidgetFilters` | Optional sell-side and buy-side filtering rules |
| `theme` | `"light" \| "dark" \| "system"` | Built-in theme. `"system"` follows the viewer's color scheme. Default: `"dark"` |
| `vars` | `Partial<MyWidgetVars>` | Theme token overrides for every theme |
| `varsByTheme` | `Partial<Record<"light" \| "dark", Partial<MyWidgetVars>>>` | Theme token overrides for one theme, applied over `vars` |
| `motion` | `"auto" \| "reduced" \| "none"` | Animation level. Default: `"auto"` |
| `className` | `string` | Applied to the widget root element |
| `style` | `React.CSSProperties` | Inline root styles applied after generated CSS variables |
| `initialSellToken` | `TradeWidgetTokenSelection` | Preselect sell token on first mount |
| `initialBuyToken` | `TradeWidgetTokenSelection` | Preselect buy token on first mount |
| `initialSellNetworkId` | `number` | Preselect sell network on first mount |
| `initialBuyNetworkId` | `number` | Preselect buy network on first mount |
| `sellNetworkId` | `number` | Requests a sell network change after mount |
| `buyNetworkId` | `number` | Requests a buy network change after mount |
| `lockSellToken` | `boolean` | Prevent changing the sell token |
| `lockBuyToken` | `boolean` | Prevent changing the buy token |
| `lockSellNetwork` | `boolean` | Prevent changing the sell network |
| `lockBuyNetwork` | `boolean` | Prevent changing the buy network |
| `onQuote` | `(payload: TradeWidgetQuotePayload) => void` | Quote resolved callback |
| `onStatusChange` | `(payload: TradeWidgetStatusPayload) => void` | Initial status, then every status change |
| `onConnect` | `(payload: TradeWidgetConnectPayload) => void` | Wallet connected callback |
| `onWalletStateChange` | `(payload: TradeWidgetWalletStatePayload) => void` | Initial wallet state, then every change |
| `onSellNetworkChange` | `(networkId: number) => void` | Sell network selected, including the first resolved selection |
| `onBuyNetworkChange` | `(networkId: number) => void` | Buy network selected, including the first resolved selection |
| `onSellTokenChange` | `(payload: TradeWidgetTokenChangePayload \| null) => void` | Sell token selected, including the first resolved selection |
| `onBuyTokenChange` | `(payload: TradeWidgetTokenChangePayload \| null) => void` | Buy token selected, including the first resolved selection |
| `onSellAmountChange` | `(amount: string) => void` | Sell amount changed, as a decimal string in token units |
| `onApprove` | `(payload: TradeWidgetTransactionPayload) => void` | Approval transaction submitted callback |
| `onSwap` | `(payload: TradeWidgetTransactionPayload) => void` | Swap or bridge transaction submitted callback |
| `onTxSubmitted` | `(payload: TradeWidgetTransactionPayload) => void` | Generic transaction submitted callback |
| `onTxConfirmed` | `(payload: TradeWidgetTransactionPayload) => void` | Generic transaction confirmed callback |
| `onError` | `(payload: TradeWidgetErrorPayload) => void` | Error callback |

See [Widget Events](/widget/advanced-setup/widget-events) for when each callback fires.

## `TradeWidgetHandle`

```ts
interface TradeWidgetHandle {
  openWalletModal(target?: "origin" | "destination"): void;
}
```

`openWalletModal` opens the widget's wallet connection flow for the requested side, using the same behavior as the widget's own controls, including an externally managed wallet when one is supplied. It is ignored while a trade's progress is shown instead of the form.

```tsx
import { useRef } from "react";
import { TradeWidget, type TradeWidgetHandle } from "@deloraprotocol/widget";

function TradePage() {
  const widgetRef = useRef<TradeWidgetHandle>(null);

  return (
    <>
      <button onClick={() => widgetRef.current?.openWalletModal("origin")}>
        Connect wallet
      </button>
      <TradeWidget ref={widgetRef} config={{}} />
    </>
  );
}
```

## `TradeWidgetConfig`

| Field | Type | Description |
| --- | --- | --- |
| `apiUrl` | `string` | Optional Delora API base. If omitted, the widget uses `https://api.delora.build`. Must be an absolute HTTPS URL; HTTP only for local development. You can point this to your own backend proxy. |
| `rpcUrls` | `TradeWidgetRpcUrlsByChainId` | Preferred endpoints, mapped from numeric chain IDs to ordered URL arrays |
| `integrator` | `string` | Quote request integrator id |
| `apiKey` | `string` | Optional Delora API key sent as `x-api-key`. Recommended only for trusted environments. |
| `fee` | `number` | Quote fee value, range `0..0.1` |
| `slippage` | `number` | Starting slippage, range `0..1`. Unset means Auto. |
| `maxSlippage` | `number` | Highest slippage a user may choose, above `0` and up to `1`. Hides Auto. |
| `lockSlippage` | `boolean` | Fixes slippage to `slippage` (Auto when unset). Default: `false` |
| `quoteRefresh` | `TradeWidgetQuoteRefreshConfig` | Automatic quote renewal timing |
| `excludeBridges` | `string[]` | Bridge keys from `/v1/tools` that are never used |
| `excludeExchanges` | `string[]` | Exchange keys from `/v1/tools` that are never used |
| `assetBaseUrl` | `string` | Base URL for relative image paths |
| `requireWalletConsent` | `boolean` | Require acceptance of Delora's Terms of Use and Privacy Policy before wallet connection. Default: `false` |
| `showPoweredByDelora` | `boolean` | Show the linked Powered by Delora label. Default: `false` |
| `poweredByDeloraPosition` | `TradeWidgetPoweredByPosition` | Label alignment. Default: `"center"` |
| `walletConnectProjectId` | `string` | Reown (WalletConnect) project id |
| `wallets` | `TradeWidgetWalletConfig` | Built-in wallet allowlist, denylist, and preferred order |
| `walletDiscovery` | `TradeWidgetWalletDiscoveryConfig` | Which discovered browser wallets the built-in picker shows |
| `routeMode` | `TradeWidgetRouteMode` | `"all"`, `"swap-only"`, or `"bridge-only"`. Default: `"all"` |
| `walletUi` | `TradeWidgetWalletUiConfig` | Wallet picker presentation and wallet controls |
| `headerUi` | `TradeWidgetHeaderUiConfig` | Quote refresh and settings buttons |
| `formUi` | `TradeWidgetFormUiConfig` | Form title, labels, amount shortcuts, and quote details placement |
| `modalUi` | `TradeWidgetModalUiConfig` | What an open dialog dims |
| `tokenPickerUi` | `TradeWidgetTokenPickerUiConfig` | Native-token pin, dust threshold, and page size |
| `tokenLogos` | `TradeWidgetTokenLogo[]` | Host logos for specific tokens |
| `tokenCatalog` | `TradeWidgetTokenCatalogMode` | `"curated"` or `"all"`. Default: `"curated"` |
| `rememberSelection` | `boolean` | Restore the user's last networks and tokens. Default: `true` |
| `tokenOrder` | `{ sell?: TradeWidgetTokenSelection[]; buy?: TradeWidgetTokenSelection[] }` | Tokens listed first in each picker |

For browser-rendered widgets, prefer not to pass `apiKey` directly from the client. Keep it on your backend and proxy the widget's Delora requests through `config.apiUrl`. See [Configure Widget](/widget/basic-setup/configure-widget#use-a-backend-proxy) for the endpoint list.

If your proxy does not serve Delora-relative image assets, set `assetBaseUrl` explicitly or proxy those asset paths as well.

When `requireWalletConsent` is `true`, the connect flow shows a consent checkbox that links Delora's own Terms of Use and Privacy Policy. The links cannot be replaced.

`include`, `exclude`, and `order` are independent. `include` is an allowlist,
`exclude` is a denylist with precedence over `include`, and `order` only moves
enabled wallets to the front without hiding unlisted wallets. These controls
apply to widget-managed wallets, not host-provided `walletOptions`.

## `DeloraWalletManagementProvider`

`DeloraWalletManagementProvider` is a convenience wrapper around `TradeWidgetWalletProvider`.

```ts
interface DeloraWalletManagementProviderProps {
  wallet?: TradeWidgetManagedWallet | null;
  origin?: TradeWidgetManagedWallet | null;
  destination?: TradeWidgetManagedWallet | null;
  children?: React.ReactNode;
}
```

If `origin` or `destination` is omitted, that side receives `wallet`. Pass explicit `origin` and `destination` when sell-side and receiver-side wallet ownership should differ.

## `DeloraAutoWalletManagementProvider`

`DeloraAutoWalletManagementProvider` detects host Wagmi and Solana Wallet Adapter contexts and wires them into the widget.

```ts
interface DeloraAutoWalletManagementProviderProps {
  evm?: UseWagmiManagedWalletOptions | false;
  solana?: UseSolanaWalletAdapterManagedWalletOptions | false;
  wallet?: TradeWidgetManagedWallet | null;
  origin?: TradeWidgetManagedWallet | null;
  destination?: TradeWidgetManagedWallet | null;
  usePartialWalletManagement?: boolean;
  forceInternalWalletManagement?: boolean;
  children?: React.ReactNode;
}
```

Defaults:

- `usePartialWalletManagement`: `true`
- `forceInternalWalletManagement`: `false`

Set `evm={false}` or `solana={false}` to opt out of one namespace. Set `forceInternalWalletManagement` to ignore all detected host contexts.
